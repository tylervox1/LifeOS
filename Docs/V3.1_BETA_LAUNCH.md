# LifeOS V3.1 — Beta Launch Execution

## Beta access
Registration can require an invite (`REQUIRE_INVITE=true`). Invite codes are generated by the admin console; only SHA-256 hashes are stored. Invite usage is atomically limited.

A public waitlist is available at `/api/public/waitlist`.

## Admin console
Open `/admin.html` after signing in to LifeOS. Enter the separate `ADMIN_API_KEY` to view:
- user count
- waitlist
- invite usage
- support tickets
- failed job count

## Scheduler fix
Gmail, Calendar, and Gmail watch jobs are now queued only for users with a connected Google account. Proactive alerts and Daily Brief jobs remain available to all users.

## Deployment
Render uses `/api/readiness`, a pre-deploy migration, and explicit secret placeholders.
Fly uses process groups and a release command for database migrations.

## Smoke test
After deployment:
```bash
APP_PUBLIC_URL=https://your-domain.example npm run smoke
```

## Launch sequence
1. configure production secrets
2. run `npm run launch:check`
3. migrate
4. deploy API/worker/scheduler
5. run smoke test
6. sign in and open `/admin.html`
7. create an invite code
8. register a fresh test user with that invite
9. connect a non-personal Google test account
10. exercise Gmail/Calendar sync and one approval-gated action
11. verify telemetry, support, notifications, and billing sandbox
12. invite a very small beta cohort
